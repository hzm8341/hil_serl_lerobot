1. 研究背景与目标

本次工作的直接目标是：按 docs/img 中图片顺序理解 HIL-SERL 仿真 demo，并在当前仓库中找到真实可运行的仿真路径。进一步的目标是，把原本偏“训练 smoke 流程”的控制逻辑，扩展成更接近工业生产思维的安全控制框架。

结论先行：原始 HIL-SERL 仿真路径更适合“训练阶段的人类接管”，不适合直接类比为“工业现场的正式运行方式”。工业化必须引入显式模式切换、超时判定和安全恢复机制。

4. 为什么机械臂会“自己动”

这个问题是本次复现里最关键的理解点之一。

原始逻辑：mode = null 时，主循环会持续从动作空间中采样动作；人工接管只是“覆盖自动动作”，不是“默认纯手动”。

这意味着：

  • smoke 配置更接近训练/演示 HIL 思想。
  • 如果不进入 intervention，机器人就会按自动动作运行。
  • 这对“训练阶段看接管机制”是合理的，对“稳定人工遥操作录示范”并不理想。
场景 是否适合自动动作 说明
训练 smoke / HIL 演示 适合 方便观察“自动策略 + 人工接管”的机制。
示范数据采集 不适合 更合理的是默认静止或明确人工模式。
工业生产 不适合 绝不应超时后回随机动作。

5. 人工接管逻辑与键位说明

当前仿真里，键盘控制的核心不是“直接替代一切”，而是控制人工接管状态。在 gym_hil_keyboard_smoke.json 中，未开启干预时环境仍可能继续执行自动/随机动作。

推荐操作顺序：先等 MuJoCo 窗口打开 → 按 i 看到 Intervention ENABLED → 再用方向键 / Shift / Ctrl 控制 → 再按 i 退出干预。
按键 作用
i开始/结束 intervention（人工接管）；必须先开启，方向键才会生效
↑ ↓ ← →末端在 X-Y 平面移动
左 Shift（按住）沿 Z 轴向下（Z-）
右 Shift（按住）沿 Z 轴向上（Z+）
左 Ctrl（按住）闭合夹爪（gripper=0）
右 Ctrl（按住）张开夹爪（gripper=2）
s结束当前 episode，标为成功
f结束当前 episode，标为失败
r重录当前 episode
c超时进入安全态后，确认重新 arm 自动模式（hold/retreat demo）

动作格式

  • dx / dy / dz：离散值，取 -1、0、+1
  • gripper：0=闭合，1=保持，2=张开

终端日志

Intervention ENABLED
Intervention input: teleop=[dx=+0, dy=-1, dz=+0, gripper=1(hold)] applied=[...] state=manual
Intervention DISABLED
Closing environment...

常见问题

  • 方向键没反应：说明还没按 i 开启干预。
  • Z 轴怎么控：按住左 Shift 向下，按住右 Shift 向上。
  • 夹爪怎么控：按住左 Ctrl 闭合，按住右 Ctrl 张开，松开即保持。
  • 按 i 后出现红色方框：MuJoCo 查看器默认把 I 绑定为惯性盒显示；当前代码会在每步后自动隐藏该调试层。
  • 退出时段错误：请使用会打印 Closing environment... 的当前版本，确保正常关闭 MuJoCo viewer。

6. 工业场景下应采用的控制策略

推荐顺序：AUTO + 明确模式切换 + 超时进入 SAFE_HOLD / SAFE_RETREAT，优先于“超时后回随机”。

自动策略包含哪些内容

  • 任务层决策：抓取、放置、重试、退出。
  • 运动生成：末端目标、速度、力控、路径约束。
  • 感知与成功判断：目标位置、抓稳检测、任务是否完成。
  • 异常恢复：轻微偏差重试、退回观察位、等待人工。
  • 安全约束：速度上限、工作空间边界、夹爪力、碰撞体积。

模式切换的真正含义

不只是“自动和人工二选一”，而是至少包括：

  • AUTO：自动策略控制。
  • MANUAL：人工接管控制。
  • SAFE_HOLD：保持当前安全状态，不再发新目标。
  • SAFE_RETREAT：退到预定义安全方向或安全姿态。
  • FAULT：更严格的错误锁定，等待人工确认。

8. 新增状态机设计

为接近工业生产的控制习惯，本次把键盘接管路径扩展成一个最小状态机。

状态 含义 退出条件
auto 自动动作或自动策略运行 按 i 进入 intervention
manual 人工接管，键盘动作覆盖自动动作 超时、关闭 intervention、或 episode 结束
safe_hold 超时后进入安全保持，输出零位移 / 中立夹爪命令 人工确认 re-arm，或再次 intervention
safe_retreat 超时后先按预设安全退让动作运动若干步 退让步数耗尽后进入 safe_hold 
AUTO
  └── 按 i → MANUAL
MANUAL
  ├── 有输入 → 继续 MANUAL
  ├── 无输入但未超时 → 继续 MANUAL（中立动作）
  ├── 超时 + hold → SAFE_HOLD
  └── 超时 + retreat → SAFE_RETREAT → SAFE_HOLD
SAFE_HOLD / SAFE_RETREAT
  └── 若 require_manual_rearm_after_timeout = true
      则必须按 c 才能恢复 AUTO

9. 新增配置项说明

字段 作用 推荐值
idle_behavior 非 intervention 时如何处理自动动作 random / hold
manual_input_timeout_s 人工接管后，多久无实际输入视为超时 1.0 ~ 3.0
timeout_behavior 超时后进入保持还是退让 hold 或 retreat
safe_retreat_steps 退让动作执行多少步 5 ~ 10
safe_retreat_action 退让动作本身 例如 [0, 0, 1, 1]
require_manual_rearm_after_timeout 超时进入安全态后是否必须人工确认恢复自动 生产建议 true

11. 红色碰撞几何体与末端标记解释

11.1 为什么会看到“红色多面体”

用户后来提供的截图表明，画面中出现的并不是任务方块，而是一组附着在机械臂各连杆与夹爪上的半透明红色多面体。这个现象对应的是 MuJoCo collision geoms 的可视化。

  • 白色外形是机器人 visual mesh。
  • 红色半透明体是碰撞模型 collision mesh。
  • 它们与机械臂刚体绑定，因此看起来像“附着在机械臂上”。

这不是异常，也不是接管逻辑错误。它更接近调试视图，用于帮助观察真实碰撞体积。

11.2 与末端 pinch 参考点的区别

在 Panda 夹爪末端还定义了一个 pinch site，用于末端控制参考点：

<site name="pinch" pos="0 0 0.145"/>

这个 site 更像控制参考点，不是截图里那种大块的红色多面体。截图中的大红体主要应理解为碰撞体显示。

13. 建议的后续研究方向

  1. 把 control_state 显示到仿真 UI 或视频录制叠层里，便于回放分析。
  2. 加入更完整的 FAULT 状态与错误码，区分超时、碰撞、感知失效、通信中断。
  3. 把超时从“统一超时”扩展成“任务阶段级超时”，例如搜索、接近、抓取、放置分别设置。
  4. 加入更真实的工业安全退让策略，而不是固定向上 retreat。
  5. 将演示模式、训练模式、生产模式拆成独立配置模板，减少误用。
推荐实践：训练阶段保留 random + intervention 的 HIL 思想；示范采集与生产演示阶段改用 hold 或 retreat；真正工业部署时默认启用 require_manual_rearm_after_timeout = true。
