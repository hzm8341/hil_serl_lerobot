1. Policies 文件夹总览

policies/ 是 LeRobot 的策略算法库。所有策略继承 PreTrainedPolicy，通过 factory.py 统一创建， 并实现相同的推理接口 select_action(batch)。

type 类别 核心文件 训练入口 典型场景
act IL policies/act/ lerobot-train 双臂/单臂模仿，action chunking
diffusion IL policies/diffusion/ lerobot-train 视觉模仿，多模态动作分布
vqbet IL policies/vqbet/ lerobot-train 离散行为 token + offset
tdmpc IL/RL policies/tdmpc/ lerobot-train 仿真控制，模型预测
pi0 VLA policies/pi0/ lerobot-train PaliGemma + Expert，大模型 VLA
pi0fast VLA policies/pi0fast/ lerobot-train π0 快速推理变体
smolvla VLA policies/smolvla/ lerobot-train SmolVLM 轻量 VLA，边缘部署
sac RL policies/sac/ rl/learner.py HIL-SERL 在线 RL
reward_classifier RL policies/sac/reward_model/ 单独训练 稀疏奖励，HIL-SERL
核心结论： policies/ 不是「所有算法都参与 RL」，而是把 IL、VLA、RL 等多种范式 放在同一套接口下。pi0、smolvla、act 等用于模仿学习；sac 用于 HIL-SERL 强化学习。

2. IL 与 RL：两条独立管线

flowchart TB subgraph IL["Pipeline A/B：模仿学习 (lerobot-train)"] IL1["pi0 / smolvla / act / diffusion / vqbet"] IL2["监督学习：policy.forward(batch) → loss"] IL3["离线 dataset 训练"] IL1 --> IL2 --> IL3 end subgraph RL["Pipeline C：HIL-SERL (rl/learner + rl/actor)"] RL1["sac + reward_classifier"] RL2["SAC critic/actor/temperature loss"] RL3["在线 replay + 离线 replay 混合"] RL1 --> RL2 --> RL3 end DATA["共用：record / LeRobotDataset / select_action"] IL --> DATA RL --> DATA

模仿学习（IL / VLA）

  • 从 demonstration 学习 obs → action 映射
  • 训练入口：python -m lerobot.scripts.train
  • 损失：行为克隆（L1、MSE、Focal loss 等）
  • 无 critic、无 reward、无 exploration

强化学习（RL）

  • 在环境中 trial-and-error，优化累积 reward
  • 训练入口：rl/learner.py + rl/actor.py（分布式 Actor-Learner）
  • 核心算法：Soft Actor-Critic（SAC）
  • 支持人类在环干预（Human-in-the-Loop）
重要： pi0、smolvla 等 VLA 没有与 SAC 做算法级融合——不会把 pi0 当作 SAC 的 actor， 也不会对 pi0 做 policy gradient。若要做「VLA 预训练 + RL 微调」，需自行设计桥接方案， 本仓库尚未内置。

3. HIL-SERL 如何结合示范数据

HIL-SERL 把人类示范当作 RL 的前置准备，在数据流层面与 IL 衔接， 而非把 IL 模型嵌入 RL 网络。

flowchart TB subgraph Actor["Actor 进程 (rl/actor.py)"] ENV["gym_manipulator 真机/仿真"] SAC["SACPolicy.select_action()"] HUMAN["人类干预 gamepad/keyboard"] ENV --> SAC HUMAN -->|覆盖动作| ENV SAC --> TRANS["收集 transition"] end subgraph Learner["Learner 进程 (rl/learner.py)"] RB_ON["Online ReplayBuffer"] RB_OFF["Offline ReplayBuffer（示范数据）"] UPDATE["SAC 更新 critic/actor"] RB_ON --> UPDATE RB_OFF --> UPDATE end TRANS -->|gRPC| RB_ON UPDATE -->|同步参数| SAC

工作流阶段

  1. 示范采集：用 gym_manipulator + 遥操作采集 demonstration（与 IL 共用数据格式）
  2. 奖励分类器（可选）：用示范训练 reward_classifier，自动判断成功/失败
  3. 混合训练 SAC：示范预填充 offline replay buffer；Actor 在线采集填入 online buffer；Learner 各采一半 batch 混合训练
  4. 人类干预：训练过程中可随时接管，干预数据同样写入 replay buffer

if cfg.dataset is not None:

4. pi0 / smolvla：VLA 模仿学习

这两个文件夹存在，是因为 LeRobot 要支持大模型时代的机器人模仿学习—— 用预训练 VLA 在少量示范上微调，比从零训练 act 更容易泛化到新任务。

文件夹算法来源骨干网络
policies/pi0/ π0 — Flow Matching VLA Physical Intelligence，HF 从 JAX 移植 PaliGemma-3B + Gemma Expert
policies/smolvla/ SmolVLA — 轻量 VLA Hugging Face 自研 SmolVLM（~450M）+ Action Expert

输入与输出

  • 输入：多相机图像 + 机器人状态 + 自然语言任务描述（如 "pick up the cube"）
  • 输出：action chunk（默认 chunk_size=50，内部维护 action queue）
  • 训练：监督学习 / flow matching，非 RL

典型微调命令

# SmolVLA
python -m lerobot.scripts.train \
  --policy.path=lerobot/smolvla_base \
  --dataset.repo_id=你的数据集 \
  --batch_size=64 \
  --steps=20000

# π0
python -m lerobot.scripts.train \
  --policy.path=lerobot/pi0 \
  --dataset.repo_id=你的数据集

与 act / diffusion 的区别

策略规模语言条件典型用途
act小（~几十 M）否固定任务双臂操作
diffusion中否视觉模仿
pi0大（~3B+）是通用机器人控制，多任务泛化
smolvla中（~450M）是轻量 VLA，边缘部署
使用注意： 需安装额外依赖 pip install -e ".[pi0]" 或 pip install -e ".[smolvla]"； 推理时需注入 task 字符串；支持异步远程推理（policy_server）。

5. ACT / Diffusion / VQ-BeT 对比

三者都属于模仿学习，都支持 action chunking（一次预测多步动作）， 但动作生成机制和核心网络结构差异很大。

flowchart TB subgraph ACT["ACT — Transformer 直接回归"] A1["ResNet 图像 feature map"] --> A2["Transformer Encoder-Decoder"] A3["可选 VAE 编码动作"] --> A2 A2 --> A4["直接输出 action chunk (L1)"] end subgraph Diff["Diffusion — 扩散去噪"] D1["ResNet + SpatialSoftmax"] --> D2["全局条件向量"] D3["随机噪声 action 轨迹"] --> D4["1D Conditional UNet"] D2 --> D4 D4 --> D5["迭代去噪 → action chunk"] end subgraph VQ["VQ-BeT — 离散 token + offset"] V1["ResNet + SpatialSoftmax"] --> V2["GPT / minGPT"] V3["Residual VQ-VAE 码本"] --> V4["Code + Offset 预测"] V2 --> V4 V4 --> V5["解码 + offset → action chunk"] end
维度 ACT Diffusion VQ-BeT
论文 Action Chunking Transformer (Aloha) Diffusion Policy (PushT 等) Behavior Generation with Latent Actions
动作表示 连续向量，直接回归 连续轨迹，扩散去噪 离散 code + 连续 offset
核心网络 Transformer Encoder-Decoder 1D Conditional UNet GPT + Residual VQ-VAE
视觉编码 ResNet → 2D feature map token ResNet → SpatialSoftmax 关键点 同 Diffusion
时序建模 单步观测为主（n_obs_steps=1） 多步观测历史（通常 n_obs_steps=2） 多步观测 + action query token
训练目标 L1（+ 可选 VAE KL） MSE 预测噪声/样本 Focal loss（code）+ L1（offset）
推理方式 一次前向 多步迭代去噪（~100 步） 一次前向 + code 采样
训练阶段 单阶段 单阶段 两阶段（先 RVQ，再 GPT）
典型场景 双臂精细操作（Aloha） 视觉推动、多模态任务 PushT，离散行为建模
一句话总结： ACT 用 Transformer 直接回归动作； Diffusion 用 UNet 迭代去噪生成轨迹； VQ-BeT 先用 VQ 离散化动作，再用 GPT 预测 token + offset。

6. ACT 架构详解

思路：观测 → Transformer → 直接输出一段连续动作，最简单直接。

图像 ──► ResNet backbone ──► 2D feature map tokens ──┐ 状态 ──► Linear 投影 ─────────────────────────────────┤ ├──► Transformer Encoder 训练时：动作序列 ──► VAE Encoder ──► latent z ────────┘ │ Transformer Decoder │ ▼ action chunk (chunk_size 步)

关键组件（modeling_act.py → ACT 类）

  • ResNet backbone：提取 layer4 feature map，每个空间位置作为一个 token
  • Transformer Encoder-Decoder：Cross-Attention 解码，图像 token + latent 条件
  • 可选 CVAE：训练时用 VAE encoder 编码目标动作序列，引入随机 latent；推理时只用 Decoder
  • Temporal Ensembling（可选）：多次预测做指数加权平均，平滑执行

损失函数

loss = L1(action_pred, action_gt) + kl_weight * KL   # use_vae=True 时
loss = L1(action_pred, action_gt)                   # use_vae=False 时

7. Diffusion 架构详解

思路：把动作轨迹当作「图像」，用扩散过程从噪声逐步去噪生成。

多步观测 (state + 图像) ──► ResNet + SpatialSoftmax ──► global_cond │ 随机噪声 [horizon × action_dim] ──────────────────────────────┤ ▼ 1D Conditional UNet (在 horizon 维度做 conv) │ 迭代 T 步 DDPM/DDIM 去噪 ▼ action chunk

关键组件（modeling_diffusion.py → DiffusionModel 类）

  • SpatialSoftmax：2D 特征图 → 少量关键点坐标（如 32 个），比 ACT 更紧凑
  • 1D Conditional UNet：在 horizon 维度做 1D 卷积，以 global_cond 为条件
  • 多步观测：缓存 n_obs_steps 步历史观测再条件化
  • DDPM/DDIM Scheduler：训练加噪、推理去噪

训练 vs 推理

  • 训练：对干净轨迹加噪，预测噪声 ε（MSE loss）
  • 推理：从纯噪声出发，迭代去噪（默认 ~100 步），比 ACT 慢
# 推理核心循环（简化）
sample = torch.randn(batch, horizon, action_dim)
for t in scheduler.timesteps:
    pred = unet(sample, t, global_cond=global_cond)
    sample = scheduler.step(pred, t, sample).prev_sample

8. VQ-BeT 架构详解

思路：先把连续动作离散化成「行为 token」，再用 GPT 预测 token， 并对每个 token 预测连续 offset 做精修。

阶段 1 — 动作离散化（Residual VQ-VAE）

action chunk ──► RVQ Encoder ──► 残差码本量化 ──► RVQ Decoder ──► 重建动作

学习动作的「字典」，把连续动作映射到有限 code。训练 n_vqvae_training_steps 步后冻结码本。

阶段 2 — 行为生成（GPT + Action Head）

历史观测 (图像token + 状态token + action_query_token) │ ▼ GPT (minGPT) │ ┌─────────┴─────────┐ ▼ ▼ Code 预测头 Offset 预测头 (Focal Loss) (L1 Loss) │ │ └─────────┬─────────┘ ▼ RVQ Decoder(code) + offset → action chunk

关键组件（modeling_vqbet.py）

  • Action Query Token：可学习 prompt，从观测序列中「查询」动作
  • GPT (minGPT)：自回归序列模型，seq2seq 预测
  • VQBeTHead：bin 预测（分类）+ offset 预测（回归）+ RVQ 解码
  • 混合表示：粗粒度离散 code + 细粒度连续 offset

9. 视觉编码差异

三者都用 ResNet，但用法不同——这是架构上容易忽略的细节。

策略视觉特征形式信息保留
ACT ResNet layer4 完整 2D feature map，每个空间位置一个 token 最丰富，token 数最多
Diffusion ResNet → SpatialSoftmax → 每通道一个 (x,y) 关键点 压缩为少量坐标
VQ-BeT 同 Diffusion，SpatialSoftmax → MLP 投影为 GPT token 同 Diffusion

ACT 保留更多空间细节，适合精细双臂操作； Diffusion / VQ-BeT 更紧凑，计算更轻。

Action Chunking 执行（三者共性）

  1. 一次预测 chunk_size（或 horizon）步动作
  2. 逐步从 queue 中取出执行
  3. queue 空时再重新预测

差异只在「如何生成」chunk：ACT 一次前向；Diffusion 多次 UNet 去噪；VQ-BeT GPT 前向 + code 采样。

10. 算法选型建议

双臂 Aloha 精细操作，要快推理

推荐 ACT

多模态动作分布（同一 obs 多种合理动作）

推荐 Diffusion 或 ACT+CVAE

动作有明显模式/阶段、离散行为结构

推荐 VQ-BeT

语言条件、多任务泛化

推荐 pi0 / smolvla

真机在线精调、人类兜底

推荐 SAC（HIL-SERL）

推理延迟敏感

ACT > VQ-BeT > Diffusion

需求推荐算法
数据量少、动作分布简单ACT
数据量大、复杂轨迹分布Diffusion
需要语言指令控制任务pi0 / smolvla
稀疏奖励、需在线探索SAC + reward_classifier
仿真模型预测控制tdmpc
